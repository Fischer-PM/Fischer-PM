## Guiding Perspective

Developer portals fail not because they lack documentation, but because they're built for the team that maintains them, not the developers who use them. The metric that exposes this is the search query that returns no results — it shows what developers needed and couldn't find. A portal that serves its maintainers well will have clean taxonomy, consistent formatting, and complete API reference. A portal that serves its users will have working examples, an honest changelog, and a path to help that doesn't route to a queue. These are not the same thing, and when teams have to choose where to invest, they usually choose the former because it's easier to measure.
